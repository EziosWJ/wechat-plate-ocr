# 调试与测试

## 先观察输入，再观察输出

1. 首页开启“本机调试面板”，重新拍照。
2. 核对“实际输入”预览：车牌是否完整、清晰、方向正确，省份汉字与末尾字符是否都在图内。
3. 切换第 1 / 2 / 3 轮输入，对照原图检查裁剪差异。提前成功时不会执行后面的轮次。
4. 在 Console 搜索 `[plate-ocr]`，查看原始返回和号码提取结果。

调试面板默认关闭。开启后只记录下一次拍照起的事件，不会补录之前的日志；console 原始 OCR 输出始终开启。

## console 日志

日志前缀结构：

```text
[plate-ocr][第1轮][+相对时间ms] 阶段: 说明
```

| 阶段 | 内容 |
| --- | --- |
| `start` | 本轮使用参考区域、扩大区域还是全图 |
| `image` | 元信息方向、解码尺寸、旋转角度、裁剪区域、OCR 输入尺寸 |
| `submit` | 调用 `runOCR` 的时间 |
| `anchors` | `addAnchors` / `updateAnchors` 的原始返回，包括文字、坐标、subtext |
| `finish` | 有效号码稳定、等待窗口结束、取消或异常等结束原因 |
| `analysis` | 有效格式候选、人工核对建议、规范化后的文本及接受/拒绝原因 |
| `metadata` / `error` | 元信息读取失败或原生能力异常 |

日志包含识别到的车牌文字。在 GitHub Issue 中分享日志或截图前，请将真实车牌、照片以及设备个人信息脱敏。

## 常见问题

### 相机权限被拒绝

点击“相机权限设置”重新授权，或直接手动输入。`app.json.permission` 不能添加 `scope.camera`，项目通过运行时 `wx.authorize` 请求相机权限。

### 页面提示当前微信不支持识别

在手机微信中测试，核对微信版本、基础库及设备能力。项目同时检测 `createVKSession`、离屏 Canvas 和 `VKSession.runOCR`；模拟器可用不代表真机可用，反之亦然。

### OCR 未返回文字

先查看实际输入是否包含完整车牌，再看 `submit` 后是否有 `anchors` 事件。没有回调与原始文字为空要分别记录，不能仅根据页面失败提示判断模型准确率。

### 已有原始文字，却没有有效号码

查看 `analysis` 中的 `decisions`：常见原因包括缺省份简称、位数不正确、含 `I/O`、不符合新能源结构或缺少可用于拼接的坐标。页面会展示原文与疑似号码，允许人工修改；不会静默替换易混淆字符。

### 车牌缺一部分，或方向不正确

对比原图与各轮实际输入。若全图能识别而首轮不行，优先检查取景框映射与裁剪余量。方向不正确可点击“照片顺时针旋转 90° 再识别”，对同一照片重试。

### 失败时等待较久

无有效格式候选时会依次等待参考区域、扩大区域和全图，每轮上限 8 秒，最多约 24 秒。期间可以取消。重复空回调不会让识别在 350ms 时提前结束，也不会无限延长等待。

## 自动检查

```sh
pnpm typecheck
pnpm test
```

或：

```sh
npm run typecheck
npm test
```

测试使用 Node 原生测试器，在内存中转译 TypeScript，不向小程序源码目录输出 JavaScript。

| 测试文件 | 验证内容 |
| --- | --- |
| `tests/plate.test.cjs` | 普通/新能源规则、分隔符、分片、车型文字干扰和人工核对建议 |
| `tests/crop.test.cjs` | 预览 cover 映射、边界裁剪和独立横纵余量 |
| `tests/rotation.test.cjs` | 四种旋转后的尺寸与图像边界 |
| `tests/vision-ocr.test.cjs` | 原生回调、等待策略、取消、全图兜底、实际像素和 console 输出 |
| `tests/page.test.cjs` | 权限拒绝、重复拍照、确认回填、取消、切后台及迟到回调 |
| `tests/markup.test.cjs` | WXML 表达式基础语法和页面配置 |

WXML 表达式检查不能代替微信编译器。导入项目后，还应在开发者工具中执行编译，并确认 WXML/WXSS 无报错。

## 真机效果记录

当前没有经过统一样本集统计的识别准确率或速度结论。建议 Android、iPhone 各测试三类车牌，每类至少 20 张，覆盖正面、轻度倾斜、反光、阴影和不同距离。

本项目没有相册入口，使用现场拍摄样本；如果对着另一块屏幕拍摄测试图片，请单独标注这类样本，避免与真实道路拍摄混合统计。无需把原始车牌照片提交到仓库。

统计口径：

- 整牌正确：人工修改前默认候选的所有字符完全正确。无结果、超时或需人工修改均计失败；人工选择其他候选成功另行记录。
- 首次耗时：重新启动小程序后的第一张；后续耗时：同次运行后面的照片。记录页面展示的识别耗时，包含解码、会话初始化和已执行的重试，不包含拍照等待或人工确认。
- 同时标注成功发生在哪一轮，以及输入图是否完整、方向是否正确。

流程验收还应覆盖：车牌位于参考框附近不同位置、手机方向变化、拒绝/恢复权限、无文字、取消、重拍、连续点击、切后台再返回，以及退出后没有车牌历史记录。
